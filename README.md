# Копи-бот Polymarket

Копирует сделки выбранных кошельков Polymarket. Каждый кошелёк настраивается
отдельно и может копироваться виртуально (без денег, по живому стакану) или
реально. Отдельная ветка бота ищет кошельки для копирования по всему
Polymarket и собирает архив для разбора.

## Как бот видит чужие сделки и почему это быстро

Бот слушает три источника параллельно. Сделку копирует тот, кто увидел её
первым; дубли из остальных источников отбрасываются.

1. **Блокчейн Polygon.** Подписка по WebSocket на событие `OrderFilled`
   биржевых контрактов Polymarket V2 с фильтром по адресам копируемых.
   Это самый быстрый публичный путь: сделка видна в момент появления блока
   (около 2 секунд после сведения ордера). Можно указать несколько
   RPC-провайдеров через запятую (`POLYGON_WSS_URLS`). Бот слушает все сразу,
   а в «🩺 Источники» видно, кто приходит первым.
2. **Поток активности Polymarket** (RTDS, `activity`). Все сделки площадки
   без ключей. Из этого же потока бот ведёт «перепись» активных кошельков
   для поиска.
3. **Опрос Data API v2** (`/v2/activity`). Это страховка на случай обрыва
   потоков. Data API v1 Polymarket отключает 24.10.2026, поэтому бот сразу
   работает с v2.

Как исполняется копия:

- **Клиент SDK создаётся один раз** и держит соединение тёплым: раз в 20 секунд
  делает лёгкий запрос.
- **Метаданные рынка (тик, neg-risk, комиссия) прогреваются заранее.** Это
  делается для токенов, которые держат копируемые. Для нового рынка прогрев
  идёт параллельно с проверкой фильтров.
- **Ордер — «защищённый» рыночный FAK с потолком цены.** SDK не запрашивает
  стакан, а сразу подписывает ордер и отправляет одним запросом. FAK исполняет
  всё, что есть по цене не хуже потолка, а остаток отменяется.
- **Перед ордером бот смотрит живой стакан** (WebSocket). Если ask уже выше
  потолка, ордер не отправляется. Это экономит время и не плодит пустые ордера.
- **Ничего медленного на горячем пути нет.** Запись в БД идёт в отдельном
  потоке, уведомления в Telegram — через очередь. JSON разбирается через
  `orjson`, цикл событий — `uvloop`.

## Настройки каждого кошелька (кнопки + свой ввод)

| Группа | Что настраивается |
|---|---|
| **💵 Размер** | процент от суммы их входа или фиксированная сумма; потолок одной сделки; доли меньше $1 копятся, пока не наберётся минимальный ордер |
| **🎯 Цена** | допустимое проскальзывание относительно их цены (центы и проценты, берётся меньшее); диапазон цен входа, которые копируем |
| **🚪 Выходы** | зеркальные продажи (они продали 40% — мы продаём 40%); докупки вкл/выкл; стоп-лосс, тейк-профит, трейлинг-стоп, максимальное время удержания |
| **🛡 Лимиты** | максимум в один рынок; порог «их сделка меньше — не копирую»; максимум открытых позиций; дневной стоп |
| **🧹 Фильтры** | быстрые крипто-рынки (5м/15м/час) и рынки перед самым концом; входы в уже идущий матч; исполнения их лимиток |
| **Режим** | ⏸ выкл / 🧪 виртуально / 🔴 реально |

**Общие настройки:**

- выключатель реальной торговли (kill switch) и пауза новых входов — выходы при этом работают всегда;
- общий дневной стоп;
- потолок суммы открытых реальных позиций;
- проскальзывание на выходе;
- автоматический забор выигрыша после резолюции.

## Статистика по каждому кошельку

Виртуальные и реальные сделки считаются раздельно:

- число копий, пропусков и неисполненных ордеров;
- PnL (реализованный и в открытых позициях);
- ROI, плюсовые и минусовые закрытия;
- комиссии и среднее проскальзывание;
- через сколько секунд после блока бот замечает сделку;
- главные причины пропусков.

Каждые `REPORT_INTERVAL_HOURS` часов (и по кнопке «📄 Отчёт сейчас») приходит
zip с CSV:

- все попытки копирования с причинами;
- позиции;
- сделки копируемых с задержкой каждого источника.

## 🔎 Поиск кошельков

**Где ищет кандидатов:**

- лидерборды за неделю, месяц и всё время по категориям;
- крупные сделки последних часов;
- крупнейшие держатели топ-рынков;
- победители месяца;
- «перепись» активных кошельков из потока.

**Как разбирает каждого.** На рынке предсказаний безубыточный винрейт равен
цене входа. Поэтому главное — не винрейт и не сумма PnL, а **edge**:
насколько итог каждой ставки лучше цены, по которой она куплена, и насколько
это статистически значимо (z-score). Кроме этого бот проверяет:

- **Честный ROI.** Закрытые позиции плюс разрешённые, но не погашенные
  проигрыши. Без последних статистика выглядит лучше реальной.
- **Зависимость от одной-трёх удачных ставок.**
- **Стабильность:** доля прибыльных недель и просадка за 90 дней.
- **Не бот ли это:** ордеров в день и серии сделок чаще 10 секунд.
- **Не маркет-мейкер ли:** покупает ли обе стороны, живёт ли на ребейтах,
  доля тейкерских сделок.
- **Доля быстрых крипто-рынков.**
- **Время удержания позиций** — успеем ли скопировать.
- **Цена через 3 и 60 секунд после их покупок** — сколько потеряет
  копирующий.
- **Доля входов по 0.90 и выше** — мало апсайда, а редкий проигрыш съедает
  всё.
- **Edge по корзинам цены и по категориям.**

**Что на выходе:**

- архив `wallets_*.zip`: `wallets.csv` с метриками, вердиктом и причинами,
  сделки и позиции лучших кошельков, `summary.txt`, `README.txt` с
  расшифровкой колонок;
- топ-10 с кнопкой «➕ копировать виртуально».

**Пришли архив в чат** — разберу глубже и скажу, кого копировать.

Режимы: быстрый поиск занимает около 15 минут, полный — около 40. Ещё есть
авто-поиск раз в 24 или 72 часа и разбор одного кошелька по адресу (команда
`/check 0x…` или кнопка).

## Развёртывание в Coolify

1. **Создай нового бота** в @BotFather и возьми токен. Это отдельный бот,
   как Chainlink-бот.
2. **Создай новое приложение** в Coolify из этого репозитория (build pack —
   Dockerfile).
3. **Подключи постоянный диск.** Persistent Storage → Volume с путём
   `/app/data`. Без него при каждом деплое теряются кошельки, настройки и
   статистика.
4. **Задай переменные** (см. `.env.example`):
   - `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — обязательно. Управление
     возможно только из этого чата.
   - `POLY_PRIVATE_KEY`, `POLY_FUNDER_ADDRESS` — только для реальных сделок.
     Без них бот работает виртуально. Если ключ тот же, что у других ботов,
     у них общий баланс USDC.
   - `POLYGON_WSS_URLS` — по умолчанию стоит бесплатный публичный
     `wss://polygon-bor-rpc.publicnode.com`. Для скорости и надёжности добавь
     свой ключ, например Alchemy (бесплатного тарифа хватает):
     `wss://polygon-bor-rpc.publicnode.com,wss://polygon-mainnet.g.alchemy.com/v2/КЛЮЧ`.
5. **Отключи Healthcheck по порту** — у бота нет HTTP-порта.
6. **Запусти бота:** `/menu` → «➕ Добавить», пришли адрес или ссылку на
   профиль. Кошелёк всегда добавляется в 🧪 виртуальном режиме.

## Порядок работы

1. Найди кандидатов (🔎) или добавь известный кошелёк. Пусть поработает
   виртуально.
2. Через пару дней пришли мне архив поиска и отчёты копирования. Отчёты
   покажут, сколько реально теряется на задержке и проскальзывании именно у
   этого кошелька.
3. Если виртуальный результат в плюсе после комиссий — переключи кошелёк на
   🔴 и включи реальную торговлю в главном меню.

## Проверка без сети

```
python tests/run_tests.py
```

Тесты прогоняют:

- разбор событий блокчейна и потока;
- склейку источников;
- виртуальные и реальные покупки и продажи (с подменённым SDK);
- стопы, резолюцию, сверку;
- метрики поиска;
- полный поиск с архивом;
- обход всех кнопок Telegram.
